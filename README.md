# Влияние топологии сети на распространение заболеваний

Исследовательский проект для сравнения эпидемических волн на сетях Barabási–Albert и Watts–Strogatz и классификации реальных городских волн по форме синтетических SEIR-траекторий.

> [!IMPORTANT]
> Результат классификации показывает сходство формы эпидемической волны с синтетическими классами. Он не доказывает, что реальная сеть контактов города имеет предсказанную топологию.

## Что делает проект

Работа состоит из двух последовательных этапов:

1. [`create_data_regular_networks.ipynb`](create_data_regular_networks.ipynb) моделирует SEIR-процесс с внешним импортом инфекции на двух типах графов и сохраняет синтетические траектории.
2. [`city_synthetic_ai_classification_analysis.ipynb`](city_synthetic_ai_classification_analysis.ipynb) извлекает признаки формы волн, обучает калиброванный `RandomForestClassifier` на синтетических данных и классифицирует реальные городские волны.

Используемые топологии:

- [Barabási–Albert](https://networkx.org/documentation/stable/reference/generated/networkx.generators.random_graphs.barabasi_albert_graph.html) — безмасштабная сеть с предпочтительным присоединением;
- [Watts–Strogatz](https://networkx.org/documentation/stable/reference/generated/networkx.generators.random_graphs.watts_strogatz_graph.html) — сеть «малого мира».

Симуляция реализована на основе модели SEIR и библиотеки [EoN (Epidemics on Networks)](https://epidemicsonnetworks.readthedocs.io/). Внешние заражения поступают по пуассоновскому процессу в течение заданного периода.

## Ограничения

- Базовая конфигурация генерирует 3 500 симуляций: 2 топологии × 7 значений `lam` × 5 значений `tau` × 50 повторов. При `N = 10 000` выполнение может занять значительное время и потребовать много памяти и места на диске.
- Генерация графов и эпидемий не имеет единого зафиксированного seed, поэтому синтетические данные не воспроизводятся побитово. Для разбиения данных и ML-модели используется `RANDOM_STATE = 42`.
- Классификатор обучается только на двух синтетических классах и не учитывает все возможные механизмы формирования реальных эпидемических волн.
- Данные и результаты не входят в репозиторий: каталог `data/` игнорируется Git.

## Входные данные

Для второго этапа нужен файл `data/indices_in_big_cities.xlsx`. Он должен содержать как минимум следующие столбцы:

| Столбец | Назначение |
|---|---|
| `town_name` | Название города |
| `cld_year` | Год наблюдения |
| `week_number` | Номер недели |
| `wd_total` | Значение недельного ряда, используемое для формы волны |
| `wda_total` | Метка эпидемического периода; ноутбук использует значение `Э` |
| `qty_total` | Дополнительный числовой показатель, проверяемый при загрузке |

Строки должны быть упорядочиваемы по городу, году и номеру недели. Анализ использует наблюдения начиная с 2010 года.

## Использование

### 1. Генерация синтетических траекторий

Откройте `create_data_regular_networks.ipynb` и выполните ячейки по порядку. Основные параметры находятся в разделе «Параметры»:

| Параметр | Значение по умолчанию | Назначение |
|---|---:|---|
| `N` | `10**4` | Количество узлов графа |
| `tmax` | `200` | Горизонт симуляции в днях |
| `iterations` | `50` | Повторов для каждой пары параметров |
| `tau_boundaries` | `0.01…0.05` | Скорость передачи инфекции |
| `gamma` | `0.08` | Скорость выздоровления |
| `alpha` | `0.1` | Скорость перехода `E → I` |
| `lam_boundaries` | `1…64`, степени двойки | Интенсивность внешнего импорта инфекции |
| `t_stream` | `20` | Продолжительность импорта инфекции в днях |

Ноутбук пересоздаёт каталог соответствующей топологии перед генерацией. Не храните там результаты, которые нужно сохранить отдельно.

Каждая траектория записывается в CSV со столбцами:

- `S` — восприимчивые;
- `E` — находящиеся в инкубационном состоянии;
- `I` — инфицированные;
- `R` — выздоровевшие;
- `Beta` — оценка интенсивности распространения между соседними временными точками.

Также создаётся `data/meta/runs.csv` со столбцами `relative_path`, `graph_kind`, `lam`, `tau` и `seed_in_graph`.

### 2. Классификация городских волн

После генерации синтетики поместите городской набор данных в `data/indices_in_big_cities.xlsx`. Затем откройте `city_synthetic_ai_classification_analysis.ipynb` и выполните все ячейки по порядку.

Ноутбук:

1. загружает синтетические траектории из `runs.csv`;
2. выделяет фиксированные окна вокруг пиков и агрегирует синтетические дневные данные по неделям;
3. выделяет городские эпидемические волны по меткам `Э`;
4. рассчитывает признаки формы и обучает калиброванный случайный лес;
5. оценивает модель на synthetic holdout;
6. классифицирует городские волны и помечает слабые совпадения.

Ключевые таблицы создаются в памяти ноутбука:

- `synthetic_ai_eval` — метрики на синтетической holdout-выборке;
- `wave_ai_classification` — классификация отдельных городских волн;
- `city_ai_summary` — агрегированные результаты по городам.

При интерпретации смотрите не только на `predicted_class`, но и на `ai_confidence`, `probability_margin` и `weak_ai_match`. Значение `weak_ai_match = True` означает, что уверенность или отрыв между классами ниже 10-го перцентиля правильно классифицированных синтетических примеров соответствующего класса.

## Локальная структура данных

После выполнения первого этапа и добавления городских данных каталог имеет следующий вид:

```text
data/
├── indices_in_big_cities.xlsx
├── meta/
│   └── runs.csv
├── simulations/
│   ├── barabasi_albert_graph/
│   │   └── lam=<value>/
│   │       └── seir_seed_<seed>.csv
│   └── watts_strogatz_graph/
│       └── lam=<value>/
│           └── seir_seed_<seed>.csv
└── splits/
    ├── train/
    ├── val/
    └── test/
```
